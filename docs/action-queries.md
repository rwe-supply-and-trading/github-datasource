# Action investigation queries

Version `2.11.0-rwe.1` adds request-driven investigation and source inventory to the existing App/PAT datasource. It does not add a collector, webhook receiver, periodic synchronization or stored workflow history. Existing configured Enterprise Cloud/Data Residency/Server endpoints and authentication remain authoritative.

| Query               | Inputs                                                                                                                             | Result                                                                                                                                                                                                                                                                                                                 |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Workflow_Run`      | owner, repository, `options.runId`, optional exact `options.attempt`                                                               | Run metadata and outcome for that exact attempt; empty/latest addresses the latest run. No duration is inferred from `updated_at`.                                                                                                                                                                                     |
| `Workflow_Attempts` | owner, repository, `options.runId`                                                                                                 | Actual available attempt numbers from the latest run metadata, newest first, with numeric keys; latest is labeled. Up to 1000 choices.                                                                                                                                                                                 |
| `Workflows`         | owner, repository, optional `options.includeAll: true`, `options.timeField: 0`                                                     | Workflow names/IDs plus a `key` field. The explicit all choice has key `__all__`, accepted by Workflow_Runs. Catalogue pagination is bounded to 1000 workflows and errors rather than silently truncating.                                                                                                             |
| `Workflow_Jobs`     | existing exact run/attempt or job inputs; optional `options.failureFirst: true`                                                    | Existing job/runner/outcome fields plus `display_name` and numeric `result_priority`. Failure-first order only affects initial catalogue ordering; explicit job IDs stay exact. Reported failed steps include their numbers.                                                                                           |
| `Workflow_Steps`    | existing exact job ID and optional run/attempt guards                                                                              | Complete chronological reported step data. Missing conclusions and unfinished durations remain null. A mismatched run/attempt returns an error.                                                                                                                                                                        |
| `Workflow_Failures` | owner, `options.repositories` (1–10 names), optional branch, `options.maxRuns` (1–200 per repository; default 100), `options.view` | `failures` lists failed/timed-out runs; `coverage` reports per-repository completeness, returned counts, check time and errors. Time range filters creation time. No job or step fan-out occurs.                                                                                                                       |
| `Action_Inventory`  | owner, `options.repositories` (1–5 names), optional `options.ref`, `options.resolveDependencies`, `options.view`                   | `commits` compares Git-based Action identities with full SHAs, matching repository identity case-insensitively while retaining declaration names; `references` exposes declaring locations and exact source links; `coverage` reports source commits, workflow counts, distinct unresolved dependencies and scan time. |

Array-valued repository variables are interpolated as individual names. Repository limits reject excessive selections rather than silently dropping repositories. Failure discovery lists failures/timeouts separately from cancellations and does not calculate an overall success ratio from incomplete results. A run search may be limited; the coverage row and frame notices preserve that boundary. Rate-limit responses stop further repository work during that request.

Action inventory reads complete YAML through the configured GitHub API. Each source ref resolves to an immutable commit; empty uses the repository default branch. Root workflow files are read before expanding dependencies. Remote Actions are identified by repository/path plus the full pinned SHA. Local Actions retain their declaration repository/source commit. Reusable workflow refs are classified separately and may resolve to a commit at scan time; they are not mislabeled as Action versions. Source snapshots are not historical execution evidence.

Reachable composite Actions and reusable workflows expand recursively. Bounds are 40 root workflow files per repository, 160 API requests including revision/directory lookups, 1000 reference paths, four dependency levels, and 1 MiB per definition. Cycles, invalid YAML, missing manifests, non-SHA Action references, inaccessible repositories and exhausted budgets remain visible. Public GitHub definitions unavailable on an Enterprise/Data Residency API host are not fetched by forwarding the App token to another host. Such dependency expansion is explicitly partial; the pinned declaration still remains available.

Commit comparison includes only full commit identities; reusable workflows, container references and non-commit Action refs remain in reference locations. It counts declared reference paths, not executions. Repeated calls to one inaccessible definition count once in the repository's unresolved-definition count. Full SHAs remain in frames and links; reference-location tables may abbreviate their visual display while retaining the full value for inspection.

New Action queries use a bounded, instance-local 30-second result cache, shared by matching selectors and panels. Catalogue/detail frames are rebuilt per caller. Requests waiting on the same installation's query gate honor cancellation. No cache refresh starts work on its own and no incremental state is persisted.

Production rollout requires building/signing this plugin release, publishing the existing private release asset, then updating the prepared Grafana pin before synchronizing dashboards using the new query types. Credentials do not need to be copied from Grafana; the existing App configuration is reused.

Rate-limit errors retain a safe marker after SDK sanitization, so further repository and definition requests stop on both primary and secondary limits. Cancelled work is not cached. Commit and reference views both expose incomplete-coverage notices. Editors keep drafts until blur, refresh when query values change and only expose controls used by the selected query.

Relative `./` Action paths inside external definitions depend on the runner checkout. Their references remain visible with unresolved checkout context; they are not assigned the external definition repository or included as verified Action SHA identities. Relative reusable-workflow imports retain the declaring workflow commit semantics. Direct local definitions in the selected source repository remain source-snapshot identities, not runtime checkout evidence.
